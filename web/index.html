펌웨어 굽기 — MCUboot + 앱

firmware/projects/<이름>/build/merged.hex 를 고른다. MCUboot 와 앱이 합쳐져 있어 한 번에 굽는다. 빈 보드도 된다.

MCUboot 를 쓰지 않는 예제는 build/<이름>/zephyr/zephyr.hex 를 고른다. MCUboot 만 따로 굽지 않는다 — 부팅할 앱이 없으면 보드가 패닉에 빠지고, 그 상태에서는 SWD 접근도 막힌다. 그때는 [전체 삭제] 로 빠져나온다.

BLE 로 앱 업데이트 (SMP)

케이블 없이 무선으로 앱만 갱신한다 (MCUboot 는 그대로). build/<앱>/zephyr/zephyr.signed.bin 을 고른다 — .hex 가 아니라 .bin 이다. 버전은 올리지 않아도 된다.

시리얼로 앱 업데이트 (SMP)

보드의 cli 포트(VCOM1) 를 고른다. 펌웨어가 SMP 프레임만 가려내므로 cli 와 같은 포트를 쓴다. 올리는 파일은 BLE 와 같은 zephyr.signed.bin 이다.

로그


  


  

    
이 페이지 — 저장소의 web/ 이
       GitHub Pages 로 올라간 것이다. 직접 돌리려면 web/ 에서
       python3 -m http.server 8777 후 http://localhost:8777
       (WebUSB 는 HTTPS 또는 localhost 에서만 동작한다).

    
되는 브라우저 — WebUSB(SWD) 와 Web Bluetooth 를 쓰므로
       Chrome / Edge / Opera (데스크톱, Android) 에서만 동작한다.
       Safari 와 Firefox 는 지원하지 않는다.

    
BLE 업데이트 — 다른 프로그램(baram-term 등)이 보드에 BLE 로 연결 중이면
       장치 목록에 보이지 않는다 (연결 중에는 광고를 멈춘다). 먼저 끊는다.

    
시리얼 업데이트 — 같은 포트를 다른 프로그램이 열고 있으면 안 된다.
       Web Serial 은 Chrome / Edge 데스크톱에서만 동작한다.

    
확정(confirm) — 업데이트 뒤 새 펌웨어는 확정 전 상태다.
       그대로 리셋하면 이전 버전으로 돌아간다. 다시 연결해 [현재 이미지 확정] 을 누르거나
       보드 cli 에서 dfu confirm 을 한다.

    
rc=6 으로 업로드가 거절되면 — 지금 도는 펌웨어가 확정 전이라
       MCUboot 가 slot1 을 되돌아갈 자리로 잡아 두고 있다. 지금 펌웨어가 멀쩡하면
       [현재 이미지 확정] 을 누른 뒤 다시 올린다.

    
연결이 안 되면 — 다른 프로그램(pyOCD, VS Code 디버거, nRF Connect)이 프로브를 쥐고 있으면 실패한다.
       먼저 닫는다. 보드의 SW1 DISABLE_SWD 는 OFF 여야 한다.

    
주의 — 이 보드의 내장 프로브는 VCOM0 를 쓰는 펌웨어가 돌면 SWD 가 죽는다
       (보고서).
       그때는 USB 를 다시 꽂는다.
