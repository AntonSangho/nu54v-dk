# 06. I2C (`firmware/projects/i2c`)

uart 예제(05) 위에 i2c 모듈을 올려, cli 의 `i2c scan` 으로 버스에 붙은 장치를 확인한다.
센서 드라이버는 다음 예제(07 shtc3)에서 추가한다.

## 1. 하드웨어

| 항목 | 내용 |
|---|---|
| 버스 | `i2c21` (TWIM), P1.02 SDA / P1.03 SCL, 400 kHz |
| 풀업 | R29/R30 2.1 kΩ → VDD_MOD |
| 연결 | Qwiic J5 (SB14/SB15), PMIC BQ25186 (SB16/SB17) |
| 활성화 | `app.overlay` 에서 `&i2c21 { status = "okay"; }` (보드 기본값은 disabled) |

**NFC 패드**: P1.02/P1.03 은 NFC1/NFC2 겸용이고, nRF54L15 `NFCT.PADCONFIG` 리셋값은 NFC 활성이다.
보드 패키지 `board.c` 에서 부팅 시(`PRE_KERNEL_1`) NFC 패드를 끈다 → 모든 프로젝트에 적용된다.

## 2. CLI 명령

```
cli# i2c scan 1                   _DEF_I2C1 버스 검색
I2C CH1 Addr 0x6A : OK            ← PMIC BQ25186

cli# i2c read 1 0x6A 0x00 4       장치 0x6A, 레지스터 0x00 부터 4바이트
1 I2C - 0x00 : 0x61
1 I2C - 0x01 : 0x00
1 I2C - 0x02 : 0x00
1 I2C - 0x03 : 0x46

cli# i2c write 1 dev reg data     1바이트 쓰기
cli# i2c begin 1                  400 kHz 로 다시 설정
```

PMIC(0x6A) 가 응답하므로 SB16/SB17 이 연결되어 있다.
SHTC3 같은 장치는 sleep 상태에서 주소에 응답하지 않아 스캔에 보이지 않을 수 있다 (07 참고).

## 3. i2c.c — 레퍼런스(nu54dk)와 다른 점

API 와 구조(`i2c_tbl`, mutex lock, CLI 핸들러)는 그대로 두고 다음만 고쳤다.

| 항목 | 레퍼런스 | 변경 |
|---|---|---|
| `i2cReadData/WriteData` | `#if 0` (예전 HAL 코드) → 항상 false | `i2c_read/i2c_write` 로 구현 (레지스터 없이 명령을 보내는 장치용) |
| `i2cReadA16Bytes/WriteA16Bytes` | `#if 0` | 16비트 레지스터 주소(빅엔디언)로 구현 |
| `i2cIsDeviceReady` | 0바이트 쓰기 | 1바이트 읽기로 ACK 확인 (TWIM 은 0바이트 전송 불가) |
| `i2cBegin` | 주파수 무시 | `i2c_configure` 로 100/400/1000 kHz 설정 |
| `i2cRecovery` | 빈 reset | `i2c_recover_bus` 호출 |
| 에러 카운트 | 증가하지 않음 | 실패 시 `i2c_errcount` 증가 |
| `i2cReadBytes` | `uint16_t` 주소의 포인터를 1바이트로 전송 | `uint8_t` 로 변환 후 전송 |

## 4. 저전력

| 항목 | 내용 |
|---|---|
| TWIM | DTS `zephyr,pm-device-runtime-auto` + `CONFIG_PM_DEVICE_RUNTIME` → 전송할 때만 켜짐 |
| 풀업 | 2.1 kΩ 풀업은 버스가 idle(High)일 때 전류 없음. SDA/SCL 을 Low 로 두지 않도록 주의 |
